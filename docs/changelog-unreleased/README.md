# 未リリースの変更メモ（フラグメント）

このディレクトリには、PRごとの変更メモ（フラグメント）を保存します。
PRごとに個別の `.md` ファイルを作成することで、複数ブランチ間でのマージコンフリクトを完全に防ぎます。

## ルール

1. **ファイル名**:
   - PR番号が分かっている場合: `<PR番号>.md`（例: `644.md`）
   - PR作成前または未定の場合: `<ブランチ名>.md`（例: `feat-ai-model-fallback.md`）
2. **内容**:
   - 来訪者から見て何が変わったかを1〜数行の箇条書き（`- `）で記述します。
   - 例:
     ```markdown
     - AI相談で、運営が選んだAIモデルが使えないときも既定のモデルで答えるようにした（エラーで止まらない） (#644)
     ```
3. **記載不要なもの**:
   - 来訪者に見えない変更（依存更新・テスト追加・リファクタ・ドキュメント修正など）は作成不要です。

## リリース時の集約

リリース担当者が本番リリース作業（`docs/RELEASE.md`）を行う際、以下のコマンドでこのディレクトリ内の全ファイルを `docs/CHANGELOG-unreleased.md` へ一括集約します：

```bash
npm run changelog:pack
```

集約後、フラグメントファイルは自動的に削除（またはクリア）されます。
