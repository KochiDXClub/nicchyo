# 💡 提案：「今月の旬（おすすめ商品）」タグ機能

## 背景：出店者インタビューから見えた課題

2026/6/14 の出店者インタビュー（7名）から、デジタルマップを「使ってもらう」上での核心的な障壁が見えました。

- 出店者は一枚岩ではなく、**観光客向け積極層 / 常連向け野菜層 / デジタル不信層**の3層に分かれる
- 不信層・高齢層は SNS 未使用で、休業などのお知らせも**口頭**。投稿型の機能は「埋まらない箱」になりやすい
- 一方で前向きな層も「**簡単な操作であれば運用できる**」「**旬・イチ押しの商品を紹介したい**」と条件付きで期待している
- 共通して「**写真が一番**」「お客さんは日曜市のインスタをチェックしている」という声があった
- 「野菜は観光客は買わないがフルーツは買う」「良心市にお客さんが流れている」など、**来訪動機の弱さ**も課題

つまり、出店者を「投稿者」にする限り不信層は脱落する。**更新負担の構造そのものを変える**必要がある、というのが出発点です。

## 提案する機能

開発・運営側が「今月の旬」コンテンツ（写真付きバナー）を用意し、**出店者はワンタップで反応するだけ**で自店情報が更新される仕組みです。出店者を「投稿者」から「リアクションする人」に変えます。

### 出店者側の体験フロー

1. 旬の時期の **約1週間前**、運営が用意した写真付きバナー（例：「文旦、はじまります」）が出店者に通知される
2. その商品を出す予定なら、バナーの 👍 リアクションボタンを押すだけ
3. 押すと、**自店バナーの「おすすめ商品」欄が自動で更新される**（個別の入力・撮影は不要）

### 来訪者側の体験フロー

1. マップを開くと「今月の旬」バナーが表示される
2. バナーをタップすると、**その商品を出しているお店がマップ上で強調表示**される
3. 「今は文旦が旬 → 出している店はここ」という形で回遊先が決まる

## なぜ効くのか

- **写真撮影を出店者に求めずに「写真が一番」を満たせる**（運営提供のバナー写真を使う）
- **ワンタップなのでデジタル不信層・高齢層でも運用できる**
- 自店バナーが自動更新されるため、**更新し続ける負担がゼロ**
- 来訪者に「今これが旬」という**来店理由**を提供でき、良心市に流れる客の引き留めにもなる
- 旬カレンダーの企画という負担は**出店者ではなく運営側**に乗る（負担を移すのが狙い）

## 詰めておきたい論点

実装前に合意しておきたいポイントです。

### 1. 「予定」と「当日」のズレ

1週間前に 👍 した商品が、当日は完売／持って来られないことがあり得ます（「行ったのに無い」問題）。

- バナーは当日まで「**出す予定**」と明示する、もしくは
- 当日朝に「今日あります／完売」をもう一段ワンタップで切り替えられるようにする

最初から「予定」と割り切る案もあり。どこまでやるか要相談。

### 2. 不信層は通知を見ない

一番更新してほしい層ほどプッシュに気づきません。網羅率を上げるため、

- 運営・家族（後継者）が**代理でタップできる導線**
- 運営が電話確認して代理 ON する運用

を逃げ道として用意しておきたい。

### 3. 写真は「運営提供がデフォルト・差し替えは任意」

共通バナー写真で基本は回りますが、こだわる出店者（高校出店者などの積極層）には**自分の写真に差し替える選択肢**だけ残す。あくまで任意で、不信層に負担を強いない。

### 4. 旬カレンダーの運用主体

「今月の旬」を誰がいつ決めるかは運営の仕事になります。夏は同時に複数の旬が重なるため、「**今月のイチ押し1つ＋サブ数品**」の構造にしておくと破綻しにくい。

## データ構造のたたき台（要議論）

```
SeasonalTag（旬タグ）
  - id
  - name           例: "文旦"
  - banner_image   運営提供の写真
  - description    一言
  - start_date / end_date  表示期間
  - is_featured    今月のイチ押しか

ShopSeasonalReaction（出店者の反応）
  - shop_id
  - seasonal_tag_id
  - status         "予定" / "あり" / "完売"（最小構成なら「予定」のみ）
  - reacted_at
```

来訪者側は `start_date <= 今日 <= end_date` の `SeasonalTag` をバナー表示し、タップで該当 `shop_id` をマップ強調する想定。

## 議論したいこと

- まず「予定のみ（論点1の最小構成）」で出すか、当日切り替えまで入れるか
- 代理入力（論点2）の運用を最初から含めるか、後回しにするか
- 1タグ運用で始めるか、複数同時タグを最初から許容するか

ご意見ください 🙏
