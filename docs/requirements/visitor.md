# 来訪者（Visitor）の機能要件

対象: 日曜市を訪れる（訪れようとしている）人。**ログイン不要で使えることが大前提**。
主な想定: 初来訪の観光客。不安・緊張を和らげ、現地で出店者と会話できる状態をつくる。

> 重要度の基準は [README.md](./README.md) を参照。S=必須 / A=重要 / B=通常 / C=補助。

## V-01 デジタルマップ【S】

**要件**
- スマホブラウザで、インストール不要で開ける。
- 日曜市の範囲・構造・雰囲気が直感的に分かり、「どこから歩き始めるか」を判断できる。
- 店舗ピンをタップするとショップバナー（V-04）が開く。
- ジャンルでの絞り込み、現在地表示（会場内外の判定）ができる。

**重要な要素**
| 要素 | 重要度 | 理由 |
|---|---|---|
| 初回表示の速さ（体感で待たされない） | **S** | 現地の電波・端末が弱い状況で使われる |
| 道・店舗ピンの位置の正確さ（`config/roadConfig.ts` が基準） | **S** | ずれると現地で信頼を失う |
| ログイン不要 | **S** | 最初の接点で離脱させない |
| ズームに応じた店舗の間引き（密度調整） | A | 300店舗が密集しても読める |
| 現在地の会場内外判定 | B | 来訪前の人にも誤解を与えない |
| 効率的ルート案内をしない | A | 設計思想。「最短ルート」は目的ではない |

## V-02 AI案内役「にちよさん」【S】

**要件**
- ナビの「相談」から開き、分からないこと・不安を自然な言葉で相談できる。
- 検索で表現しにくい曖昧な悩みに答え、判断しきれないことは「出店者に聞いてみる」へ誘導する。
- 共通ナレッジと出店者ごとのナレッジ（RAG）を根拠に答える。
- 店舗単位の相談（ショップバナーから）と、「このへん」パネルの追い質問が同じバックエンドを使う。

**重要な要素**
| 要素 | 重要度 | 理由 |
|---|---|---|
| 事実の正確さ（ナレッジに無いことを断定しない） | **S** | 誤案内は現地での不利益に直結 |
| 出店者の会話へつなぐ導線 | **S** | 「検索→相談→会話」の核 |
| 応答の待ち時間（ストリーミング） | A | 離脱防止 |
| 土佐弁・複数キャラの掛け合い | B | 世界観。正確さより下位 |
| 会話ログの記録（匿名・改善用） | B | 管理者のAI改善（A-12）に必要 |
| 不適切入力・プロンプトインジェクション対策 | A | 公開機能のため |

## V-03 店舗検索【S】

**要件**
- カテゴリ・条件で絞り込み、店舗をリストで網羅的に確認できる。
- 結果からショップバナー（V-04）を開ける。

**重要な要素**: 網羅性（掲載漏れ・非公開店舗の混入がない）**S** / 即時性 A / 店舗コード（001〜300）での直接アクセス A。

## V-04 ショップバナー【S】

**要件**
- 店名・カテゴリ・短い紹介を中心とした最小限の情報。「今日のお知らせ」（出店者の近況）・商品・SNS・決済方法・AI相談ボタンを含む。
- マップ・検索のどちらから開いても同じ表示。QR / `/shops/001` の URL でも開ける。

**重要な要素**: 情報量を抑える（会話を妨げない）**S** / 「今日のお知らせ」は有効期限内のみ表示 **S** / 店舗コード↔ID変換は `lib/shops/route.ts` を使う A。

## V-05 日曜市カレンダー【A】

**要件**: 開催予定・荒天中止・特別開催を確認できる。マップ・近況の告知バーとデータを共有する。
**重要な要素**: 「今週やっているか」の正しさ **S**（来訪前最大の不安）/ 荒天中止の即時反映 **S** / 出店予定・イベント表示 B。

## V-06 近況【A】

**要件**: 出店者が投稿した当日の写真・お知らせを閲覧。匿名ハートのみ可能（1投稿1ハート、ログイン不要）。
**重要な要素**: 発信元を出店者に限定（来訪者投稿はしない）**S** / 古い投稿が残らない（期限・直近31日）A / 不適切投稿の非公開化（A-04 と連動）A。

## V-07 おでかけサポート【A】

**要件**: お手洗い・休憩ベンチ・公共交通のりばを選び、マップ上で最寄りを案内。
**重要な要素**: 位置データの正確さ **S** / マップ上で現在地から最寄りが分かる A。

## V-08 お気に入り【B】

**要件**: 店舗をお気に入りに保存し一覧で見返せる。現状は localStorage、サーバー同期化は [#502](https://github.com/KochiDXClub/nicchyo/issues/502)。
**重要な要素**: ログインなしで使える **S** / 端末を変えても失われない（同期化後）B。

## V-09 〜 V-13（要点のみ）

- **V-09 このへん**【B】: 画面中心付近の店舗要約と最大9件のレコメンド。過度な誘導をしない（A）。
- **V-10 問い合わせ・FAQ・規約**【B】: 問い合わせは管理者の受信トレイ（A-03）へ届くこと（A）。プライバシーポリシーの掲載は法的に必須（A）。
- **V-11 アカウント**【C】: 来訪者の利用に **必須にしない**（S の制約）。Google ログイン対応。
- **V-12 買い物バッグ**【C】: 廃止決定。**この上に新しい設計を積まない**。
- **V-13 紹介系ページ**【C】: プロジェクトの背景・協働の信頼性を伝える。
