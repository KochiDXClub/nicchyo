# 出店場所と出店予定（公開連携は未完了）

- 日曜市の住所は `512` や `183-1` のように、本番号と必要な枝番で表す。場所には内部IDを使用し、住所の表記を店舗のIDにしない。
- 同じ店舗は複数の場所に紐づけられ、同じ場所には複数の店舗を紐づけられる。場所内の店舗番号は住所の枝番とは別に保存する。紐づけ前の店舗に番号はない。
- 場所内の店舗番号は登録時に場所ごとに自動採番し、出店終了後も他店へ再利用しない。同時登録でも一意性を守る。出店終了・再開の期間を残し、同じ店舗が戻っても番号を変えない。
- 繰り返しの規則は登録期間に紐づく。出店が終了すると予定を出さず、再開しても前回の繰り返しを自動で復活させない。
- 予定の規則は毎週、基準日から隔週、第1〜第5日曜を区別する。特定日の出店・休みは規則に優先し、未設定と休みを区別する。異なる店舗の規則が同じ場所・日付に重なった場合は競合として返す。
- 出店予定管理では場所別と店舗別に直近の予定を確認し、登録・終了・繰り返し・特定日の例外を管理する。現場登録は店舗の出店先を表示し、同じ予定管理へ移動できる。
- 旧登録や旧配置は確認用として表示する。現場登録では最新の旧配置履歴を現場観測と区別して表示し、その記録だけから現在の公開を保証しない。開始日や繰り返しを推測して自動移行しない。
- マップ保存・スナップショット復元は地図の状態だけを変更し、日付別の配置履歴を変更しない。履歴のある場所を消す操作は拒否し、保存と配置への同時書き込みを直列化する。旧画面からの店舗情報・日付なしの配置変更は拒否する。
- 旧単一場所APIによる上書きは拒否し、現場観測は自動で地図に反映しない。旧データの移行確認が完了するまでは新しい予定データを公開マップへ接続しない。
- 公開マップの店舗IDは現在は場所番号で、お気に入りと共有URLも参照する。店舗が入れ替わっても別店舗のお気に入りやURLにならない識別子・移行を実装するまで、予定の公開切り替えを提供しない。
- 管理画面の予定表示は開催カレンダーの中止・休みも参照する。公開連携時も開催状況と予定の競合を安全に扱う。

### 出店予定管理の場所選択

出店予定管理では場所を読み取り専用の地図または一覧から選べる。選択は両方で同期し、選択した場所の店舗と予定を表示する。地図上に位置のない場所も一覧から選択できる。住所や位置の編集はマップ編集画面で行う。モバイルでは画面のスクロールを妨げないよう、地図は二本指で移動する。

## 公開移行までの制約

旧公開マップは `location_assignments` を参照しており、新しい予定を保存しても公開配置は変わらない。現在のスタックには、既存の公開配置を安全に変更する代替手段がまだない。旧配置の運用手順と店舗固有 ID・お気に入り・共有 URL の移行を実装して検証するまで、これらの PR を develop や本番へ順次適用しない。

### 公開店舗 ID と旧番号の扱い（移行準備中）

- `vendors.public_shop_id` は 1000 以上の変更不可の番号で、旧 URL の場所番号（001〜999）とは別の名前空間にする。店舗の場所が変わっても番号は変わらない。
- 旧番号には異なる時期に複数店舗が存在し得る。管理者が証拠を確認した対応だけを `legacy_shop_identity_aliases` に記録し、未確認の番号を推測で店舗に紐づけない。`legacy_shop_identity_candidates` は既存の配置履歴と現場登録の場所から候補を列挙するが、履歴の欠落があり得るため単独候補も自動確定しない。確定後は別店舗に変更できず、店舗削除後も番号の記録を残す。
- この DB 基盤はまだ公開 URL、ブラウザーのお気に入り、地図には接続していない。移行用の管理者画面、非公開店舗の扱い、旧 URL の案内、お気に入りの未解決データを保持する移行と、予定の公開反映を実装・検証するまで公開切り替えを行わない。
