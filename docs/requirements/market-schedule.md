# 出店場所と出店予定の土台（未接続）

- 日曜市の住所は `512` や `183-1` のように、本番号と必要な枝番で表す。場所には内部IDを使用し、住所の表記を店舗のIDにしない。
- 同じ店舗は複数の場所に紐づけられ、同じ場所には複数の店舗を紐づけられる。場所内の店舗番号は住所の枝番とは別に保存する。紐づけ前の店舗に番号はない。
- 場所内の店舗番号は登録時に場所ごとに自動採番し、出店終了後も他店へ再利用しない。同時登録でも一意性を守る。出店終了は紐づけを削除せず `ended_at` で記録し、同じ店舗が戻ったときは同じ紐づけを再開する。
- 出店終了・再開を予定の計算へ接続する際は、終了前の履歴を保ちながら終了後の予定を出さない期間の履歴が必要。現在の `ended_at` だけでは複数回の終了・再開を正確に表せないため、画面への接続前に期間履歴を追加する。
- 予定の規則は毎週、基準日から隔週、第1〜第5日曜を区別する。特定日の出店・休みは規則に優先し、未設定と休みを区別する。異なる店舗の規則が同じ場所・日付に重なった場合は競合として返す。
- 本段階のテーブルは管理者向けの土台であり、既存の画面・公開マップへ接続されていない。既存データの自動移行や本番DBへの変更は行わない。
- マップ保存・スナップショット復元は地図の状態だけを変更し、日付別の配置履歴を変更しない。履歴のある場所を消す操作は拒否し、保存と配置への同時書き込みを直列化する。旧画面からの店舗情報・日付なしの配置変更は拒否する。
- 親PRの `vendors.market_place_id` とその単一場所制約、現場登録の単一場所UI、公開マップの「最新の配置」選択を改修するまで、複数場所の運用には対応しない。
- 公開時は開催カレンダーの中止・変更日も参照する。予定の規則があるだけで出店確定とは扱わず、管理者の確認状態や店舗側の変更希望の扱いを実装する。
