# 高知市（市役所）の機能要件

対象: 高知市の日曜市ご担当者（商業振興課 街路市担当など）。
ロール: `city_official`。運営（`admin` / `moderator`）とは別系統で、**`/admin/*` と `/api/admin/*` には入れない**。
入口は `/city`、API は `/api/city/*`（`lib/auth/requireCityApi.ts` が `city_official` と `admin` だけ通す）。

> ロールを付与できるのは admin だけ（`/admin/users`）。担当者が変わったら、個人アカウントごとに付与・解除する。
> 重要度の基準は [README.md](./README.md) を参照。

## 機能一覧

| ID | 機能 | 重要度 | 状態 | 画面 |
|---|---|---|---|---|
| C-01 | 開催ステータスの更新（開催／荒天中止／特別開催／臨時休市と一言）と更新履歴 | **S** | ✅ | `/city` |
| C-02 | 利用状況・日曜市の記録の閲覧と集計CSV | A | ✅ | `/city`、`/api/city/export` |
| C-03 | サイト内・出店者へのお知らせの発信 | A | ✅ | `/city/outbox`、`/api/city/announcements`、`/api/city/vendor-notices` |

## C-01 開催ステータスの更新【S】

**要件**: 市役所が公式に「今週やるか／中止か」を更新し、マップと近況ページの最上部に反映する。運営の `/admin/calendar` と同じ部品・同じ保存の作法（選んだだけでは公開されず、「保存する」で公開）。
**更新できる日付**: 今日から8週先までの日曜だけ（画面で選べるのは今後4回）。過去の開催実績や、日曜以外・遠い先の日付は API でも受け付けない（運営は従来どおり）。
**重要な要素**: **誰がいつ何を変えたかの記録 S**（`admin_audit_logs` の `actor_role` が `city_official`）/ 検証・保存は運営と共通（`lib/market/`）で、片方だけ緩まない A / 返すのは公開列と更新履歴だけで、メールアドレスや ID は返さない A。

## C-02 利用状況・日曜市の記録の閲覧【A】

**要件**: Web の来訪者数（直近28日）、その年の開催実績、カテゴリ別の出店数を表示し、集計CSV（日別来訪者数・開催実績・カテゴリ別出店数）をダウンロードできる。
**重要な要素**: **来訪者が `/analysis` で見られる範囲を超えない S**（本人のセッション＝RLS ありで取得し、service role を使わない）/ 個票（来訪者キー・検索語・AI の質問）を出さない S / CSV の数式インジェクション対策（`lib/utils/csv.ts`）A / 「現地の来場者数ではなく Web の来訪者数」と明記 A。

## C-03 サイト内・出店者へのお知らせの発信【A】

**要件**: 市役所が、来訪者向けの「サイト内のお知らせ」（地図ページ上部と `/news`）と、全出店者向けの「出店者へのお知らせ」を出せる。運営の `/admin/outbox` と同じ部品・同じ検証・同じ操作ログ（`lib/announcements/announcementRoutes.server.ts`、`lib/vendor/noticeRoutes.server.ts` を共有）。
**範囲の線引き**: サイト内のお知らせは**自分が投稿したものだけ**見て・直して・消せる（運営の投稿は触れない）。出店者へのお知らせは**差出人が「高知市から」に固定**（API 側で上書き。「運営から」を名乗れない）で、高知市名義のものだけ見て・取り下げられる。運営（admin）はどちらも全件。
**重要な要素**: **誰がいつ何を出したかの記録 S**（`admin_audit_logs` の `actor_role`）/ 差出人のなりすまし防止 S / 同一オリジン確認と回数制限 A。
**メール配信は与えない**（登録ユーザー全員に届き、取り消せないため）。

## 与えない権限

ユーザー管理・ロール付与、監査ログ全体、AI の質問原文・問い合わせ・通報、出店者の連絡先、店舗・地図の編集、各種設定、危険な操作、メール配信。
