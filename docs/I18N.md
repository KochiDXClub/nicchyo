# 多言語対応（i18n）

計画の全体は `/mnt/project-files/i18n/multilingual-plan.md`（案）。ここには「今のコードがどう動くか」だけを書く。

## 今できること（フェーズ1の土台）

- 対応ロケールは `lib/i18n/config.ts` の `LOCALES`（日本語 `ja`・英語 `en`）。日本語が原文で、URL は無印。英語は `/en/map` のように頭に `/en` を付ける
- ロケールは `proxy.ts` が URL のプレフィックス → Cookie（`nicchyo-locale`）→ 日本語 の順で決め、`x-locale` ヘッダーでサーバーへ渡す。`/en/…` はロケールを外したパスへ書き換えて描画する（ページの置き場所は変えない）
- `app/layout.tsx` の `<html lang>` はロケールに連動する
- サーバーコンポーネントでは `getLocale()`（`lib/i18n/server.ts`）で今のロケールを読む
- メニュー下部の言語切替（`components/navigation/LanguageSwitcher.tsx`）が Cookie を書いてページを読み直す。Cookie があるので、`/en` が付いていないリンクをたどっても英語のまま
- 文言は `siteTextFor(key, locale)`。訳は `content/i18n/<locale>.json` に置き、無いキーは日本語の原文に戻る

## 画面の文言を訳す（辞書）

- 画面の固定の文言は `t("日本語の原文")` で訳す。クライアントは `useT()`（`lib/i18n/LocaleContext.tsx`）、サーバーは `await getT()`（`lib/i18n/server.ts`）
- 訳は `content/i18n/ui.en.json`（キーが日本語の原文）。無い文言は日本語のまま出る
- 変数を含む文言は `{名前}` で書き、呼び出し側で `.replace()` する（例: マップ案内のジャンル検索）
- `t("…")` に書いた日本語が辞書に無いと `lib/i18n/translate.test.ts` が落ちる。日本語の原文を直したら辞書のキーも同じに直す
- シートで編集する文言は、クライアントでは `useSiteText()`、訳は `content/i18n/en.json`（下記）

## 文言の訳を足す

1. `content/site-copy/texts.json` のキーを `content/i18n/en.json` に同じキーで追加する
2. そのページで `siteText(key)` ではなく `await getLocale()` と `siteTextFor(key, locale)` を使う（FAQページが見本）

英語化済み: FAQ の見出し・説明、ナビ・メニュー、マップの案内（はじめての方へ）。hreflang・sitemap の言語別URLは今後のPR。

## 店舗データの翻訳

出店者が日本語で入力した店名・おせっかいコメント・出店スタイルの自由記述・商品名を、AI が訳して `shop_translations` に保存する（`lib/i18n/shopTranslation*.ts`）。

- 雨天対応・支払方法・出店スタイルの選択タグ・定型の出店日は、`content/i18n/ui.en.json` の固定訳を表示する。保存キーは変えず、AIへの送信・変更検知から除外するため、選択肢だけを変えてもAIを呼ばない。AI訳が未登録でも固定訳は表示される
- 選択肢を追加するときは共通辞書にも訳を追加する。未知のタグや出店日の自由記述は原文を表示する
- 翻訳形式は v2。旧形式の雨天対応のAI訳は使わない。旧形式で保存済みの自動訳は次の同期から上限件数ずつ再翻訳される（確認済みの訳は自動上書きしない）
- 原文が変わると `source_hash` が合わなくなり、次の同期で訳し直す。`status = 'reviewed'` の行は上書きしない（運営が直した訳を守る）
- 表示は `fetchPublicShops(locale)` が訳を重ねる。`/api/shops?locale=en` も同じ。訳が無い店は日本語のまま出る
- お気に入りは商品名の日本語の原文で保存する。訳した商品名は `Shop.productOriginalNames`（訳 → 原文）で引き戻す
- 300文字を超える項目は訳さず、日本語のまま出す（切り詰めた訳で全文を置き換えないため）
- 店名は「ローマ字（日本語）」で出す。看板との照合ができるように
- 定期同期: `vercel.json` の Cron が毎日 18:00 UTC（日本時間 翌日03:00）に `GET /api/admin/shop-translations` を呼ぶ。既存の埋め込み同期（17:00 UTC）とは時間を分ける。1回につき各翻訳先言語で最大30店舗を処理し、残りは次回に回す
- 手動同期: 管理者が `POST /api/admin/shop-translations`（`{ locale?: "en", limit?: number }`）を呼ぶ
- 本番で定期実行する前に `20261020100000_create_shop_translations.sql` を適用し、Vercel の本番環境に `CRON_SECRET`・`SUPABASE_SERVICE_ROLE_KEY`・`OPENAI_API_KEY` と Supabase の接続設定を用意する。Vercel Cron は `CRON_SECRET` を Bearer トークンとして送る。定期実行は本番デプロイ後に有効になる
- 実行結果は Vercel の Cron ログで確認する。レスポンスの `results` にある `pending`・`translated`・`failed` を確認し、`failed > 0` や残件の増加が続く場合は認証・AI API・DB のログを調べる（HTTP 200 でも個別店舗の翻訳が失敗している場合がある）
- AI のモデルは管理画面の「translation」用途で変えられる（行が無ければ `lib/ai/models.ts` の既定値）

## にちよさん（AI）の英語対応

`x-locale` ヘッダ（proxy が付ける）で言語を読み、`lib/grandma/prompts/languageRules.ts` の指示をプロンプトの可変部分に足す。日本語のときは何も足さない。旅程の JSON は id・name・キーを保ったまま、文章だけ訳す。

## 確認のしかた

`npm run dev` で起動し、`/faq`（日本語）と `/en/faq`（英語）の `<html lang>` と `<title>` を見る。`/en/…` を一度開くと Cookie が付き、以後 `/faq` も英語になる。日本語に戻すにはメニュー下部の言語切替を使う。

## 相談ページ（/consult）の英語対応

画面の固定文言・キャラクターの名前と紹介・最初のひとこと・候補の質問は `content/i18n/ui.en.json` に訳がある。候補の質問は訳した文をそのまま AI に送るので、英語のまま回答が返る。キャラクターの台詞や候補の質問を足したら辞書にも足す（`translate.test.ts` が抜けを検出する）。
