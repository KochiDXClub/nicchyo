# 多言語対応（i18n）

計画の全体は `/mnt/project-files/i18n/multilingual-plan.md`（案）。ここには「今のコードがどう動くか」だけを書く。

## 今できること（フェーズ1の土台）

- 対応ロケールは `lib/i18n/config.ts` の `LOCALES`（日本語 `ja`・英語 `en`）。日本語が原文で、URL は無印。英語は `/en/map` のように頭に `/en` を付ける
- ロケールは `proxy.ts` が URL のプレフィックス → Cookie（`nicchyo-locale`）→ 日本語 の順で決め、`x-locale` ヘッダーでサーバーへ渡す。`/en/…` はロケールを外したパスへ書き換えて描画する（ページの置き場所は変えない）
- `app/layout.tsx` の `<html lang>` はロケールに連動する
- サーバーコンポーネントでは `getLocale()`（`lib/i18n/server.ts`）で今のロケールを読む
- メニュー下部の言語切替（`components/navigation/LanguageSwitcher.tsx`）が Cookie を書いてページを読み直す。Cookie があるので、`/en` が付いていないリンクをたどっても英語のまま
- 文言は `siteTextFor(key, locale)`。訳は `content/i18n/<locale>.json` に置き、無いキーは日本語の原文に戻る

## 画面の文言を訳す（辞書）

- 画面の固定の文言は `t("日本語の原文")` で訳す。クライアントは `useT()`（`lib/i18n/LocaleContext.tsx`）、サーバーは `await getT()`（`lib/i18n/server.ts`）
- 訳は `content/i18n/ui.en.json`（キーが日本語の原文）。無い文言は日本語のまま出る
- 変数を含む文言は `{名前}` で書き、呼び出し側で `.replace()` する（例: マップ案内のジャンル検索）
- `t("…")` に書いた日本語が辞書に無いと `lib/i18n/translate.test.ts` が落ちる。日本語の原文を直したら辞書のキーも同じに直す
- シートで編集する文言は、クライアントでは `useSiteText()`、訳は `content/i18n/en.json`（下記）

## 文言の訳を足す

1. `content/site-copy/texts.json` のキーを `content/i18n/en.json` に同じキーで追加する
2. そのページで `siteText(key)` ではなく `await getLocale()` と `siteTextFor(key, locale)` を使う（FAQページが見本）

英語化済み: FAQ の見出し・説明、ナビ・メニュー、マップの案内（はじめての方へ）。画面UIの文言の辞書化、店舗データの翻訳、AI の多言語化、hreflang・sitemap の言語別URLは今後のPR。

## 確認のしかた

`npm run dev` で起動し、`/faq`（日本語）と `/en/faq`（英語）の `<html lang>` と `<title>` を見る。`/en/…` を一度開くと Cookie が付き、以後 `/faq` も英語になる。日本語に戻すにはメニュー下部の言語切替を使う。
