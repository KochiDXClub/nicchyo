# 未リリースの変更

`develop` にマージ済みだが、まだ本番（`main`）に出ていない変更の記録。

**書き方**: PRを `develop` へ出すときに1行追記する。来訪者から見て何が変わったかを一言で書く。

```markdown
- 日曜市カレンダーに出店予定と旬を表示するようにした (#444)
```

来訪者に見えない変更（依存更新・テスト追加・リファクタ・ドキュメント）は書かなくてよい。

このファイルは `.gitattributes` で `merge=union` にしてある。複数のPRが同じ「## 一覧」直下に
行を足してもコンフリクトせず、両方の行が残る（順番は前後することがある。リリース時に整えればよい）。
そのぶん本文の説明を書き換えたときは、両方の版が並んで残ることがあるので目視で確認する。

リリース時にこの内容を `app/about/versions.ts` へ転記し、下の一覧を空にする。
運用の詳細は [docs/RELEASE.md](./RELEASE.md) を参照。
