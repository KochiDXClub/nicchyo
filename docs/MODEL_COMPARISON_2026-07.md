にちよさんの AI相談（`/consult`, マップのミニチャット）で使用するLLMモデルの選定検討のため、
実際の system prompt を使い、同じ15問を7モデルに投げて比較した記録。

## 方法

- 使用モデル: `gpt-4o-mini`, `gpt-5.4-mini`, `gpt-5.4-nano`, `claude-haiku-4-5`,
  `claude-sonnet-5`, `deepseek-v4-flash`, `gemini-3.1-flash-lite`
- 各社の公式APIを直接利用（third-party非経由）
- `buildGrandmaAiSystemPrompt` 等、本番と同じプロンプト生成コードを使用
- キャラクター・会話パターンは全モデル・全質問で固定し、条件を揃えた
- 店舗データは **全て synthetic**（本物の店舗データではない）

nicchyo の実際のプロンプトサイズ（約1,200 input token + 約250 output token/質問）で試算すると、

量ではモデル間のコスト差は実質的に無視できるレベル。**

## プロンプトキャッシュの検証結果

system prompt の固定部分（会話ルールなど）を先頭に、変動部分（キャラ選出・会話パターン）を
末尾にくるよう並び替えた上で `usage.prompt_tokens_details.cached_tokens` を実測した。

**結果: `cached_tokens: 0`。プロンプトキャッシュは発動しなかった。**

OpenAI のプロンプトキャッシュは、固定プレフィックスが 1,024 token 以上でないと発動しない仕様
だが、nicchyo の system prompt の固定ブロックはそれに届いていない。並び替え自体は無害なため
維持しているが、**現状のプロンプトサイズでは prompt cache によるコスト削減効果はない**。
将来 system prompt が大きく育った場合（few-shot例の追加など）に活きる可能性がある。

## 結論

- 現行の `gpt-4o-mini` は速度・安定性ともに問題なく、コストも最安クラス
- 土佐弁の自然さを重視するなら `claude-sonnet-5` が頭一つ抜けているが、速度とコストのトレード
  オフがある
- `deepseek-v4-flash` は最安値だが、15問中2問で応答が不完全になっており、現状では安定性に懸念
- `gemini-3.1-flash-lite` は圧倒的に速いが、1回サービス側のエラーが発生している
- 店舗データが全て synthetic のため、この結果は「言語・文体の品質」の比較として有効。実際の
  店舗推薦の精度比較は、本物のデータが揃ってから改めて行う必要がある
